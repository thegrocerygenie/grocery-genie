## Learned in session 1

- **Permission checks in worktrees** refused several commands:
  - `su`;
  - `git -C <another worktree>`;
  - `export ... && gg-verify` chains (run single commands with the variables inline);
  - aggregate SQL through `gg-verify sql`;
  - once, a subagent's own `git commit`/`git push` ("Unrequested Commit in a Connected App").

  Every brief tells agents: if refused, stop and report, never work around it. When a subagent is refused, do not redo the action yourself without asking the user, except for restoring the environment you own (Postgres and Redis).
- **The container can restart mid-session.** Postgres and Redis then die; `uptime` shows it. Restart Postgres from the existing data directory with `su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /var/lib/postgresql/ggdata -o '-p 54440 -k /tmp' -l /var/lib/postgresql/gg.log start"`. Restart Redis with `redis-server --port 54441 --daemonize yes --save ""`. Then resume the agent with SendMessage.
- **`apt-get install postgresql-16-pgvector`** needs `apt-get update` first. psql's `-c` cannot take a list built from `$(...)`; create one database per command.
- **Squash vs merge:** `verify-budget-alerts` reads a "Sync commit" SHA, which must exist on `main`. Merge PRs that move it with `merge_method: merge`; #88 did. Squash everything else.
- **Worktree hygiene:** agents symlink `mobile/node_modules` into their worktree. Remove the symlink before committing; the stop hook flags it. `.claude/worktrees/` is in `.git/info/exclude`, local to each clone.
- `git push` once hung for more than 2 minutes at negotiation, then succeeded. Wrap it in `timeout 300`.
- `merge_pull_request` needs the full 40-character `expectedHeadSha`.
