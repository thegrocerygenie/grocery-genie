references it. I walked the DoD checklist directly. For the story boxes I used
the `verify-acceptance` method (satisfied = the code handles it; tested = a test
would fail if it broke), but I did not write any tests or fixes.

security. I checked the claims marked ✔ myself in the code. The rest are the
agents' findings with file:line evidence, which I didn't recheck.

## LLM extraction quality

## Data integrity

### 16. Budget spend = sum of confirmed items — 🟡 Partial

✔ Spend queries filter `status == "confirmed"` but **not `deleted_at`**
(`budget_service.py:163-200`), so a soft-deleted confirmed receipt still counts
toward the budget. Tests: `test_spending_excludes_pending`,
`test_spending_with_receipts`. No test compares against an independent SQL sum.

### 17. No orphaned line items — 🟡 Partial

FK is NOT NULL with ORM `delete-orphan` (`database.py:173-184`), but the migration
FK has no `ondelete` (`20260418_0000_initial_schema.py:107-109`), there's no
30-day purge of soft-deleted receipts, and SQLite tests don't enable
`PRAGMA foreign_keys`. No test.

### 18. Item mappings persist + apply on next scan — 🟡 Partial

Written at `receipt_service.py:415-418,612-635`; read during processing at
`:147-154`. ✔ When a correction changes **both** name and category, `raw_name`
is overwritten first (`:377`), so the mapping is keyed on the corrected name.
The next scan's raw extracted name won't match it. Category-only corrections
work. No correct → re-scan → assert test.

### 19. Original images stored + retrievable — 🟡 Partial

Saved at `receipts.py:169-197`, served via owner-checked route `:226-235`; tests
`test_receipt_image_served_to_owner`, `test_user_isolation_receipt_image`.
Manual-entry confirmed receipts have no image. Storage is local disk only. The
mobile app can't display the image (see RC-04).

## Security

### 20. Auth on every route except health — ✅ Met

Only `GET /health` and the expected auth flows (sign-up, sign-in, refresh,
verify-email, resend-verification, forgot/reset-password, apple, google,
email-change/confirm) skip `get_current_user`. Tests:
`test_unauthenticated_returns_401` (one route only), `test_health_no_auth`.
Note: `/docs`, `/redoc`, `/openapi.json` are exposed (`main.py:56-60`).

### 21. User A can't access User B's data — 🟡 Partial

Owner filters are in place, and isolation tests cover receipt list/get/image,
budgets and notifications. No cross-user tests for receipt PATCH/confirm,
DELETE, restore, thumbnail, or budget PATCH/DELETE.

### 22. Rate limits (50/hr submissions, 300/min reads) — 🟡 Partial

Configured values match (`config.py:44-45`). The limiter is in-memory per process
and keyed by the raw bearer token (`rate_limit.py:39-46`), so it doesn't hold
across workers, and rotating tokens get fresh buckets. 50/hr applies to every
write, not only receipt submissions. No 429 test for either limit.
