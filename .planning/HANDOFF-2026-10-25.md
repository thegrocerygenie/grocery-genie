## Environment gotchas

These aren't written down anywhere else in the repo.

- **Python.** System `python3` is 3.9; the backend needs 3.12. Create the
  venv with `uv venv --python 3.12 backend/.venv`, then
  `uv pip install --python backend/.venv/bin/python -e "backend[dev]"`.
  The tools live in `backend/.venv/bin/` and aren't on PATH.
- **Database URL.** The config defaults to `localhost:5432`, but
  docker-compose publishes Postgres on **54440** and Redis on **54441**,
  and there's no `.env`. Migrations need:
  `export GG_DATABASE_URL="postgresql+asyncpg://grocery_genie:grocery_genie_dev@localhost:54440/grocery_genie"`.
  Celery locally needs `GG_REDIS_URL=redis://localhost:54441/0`.
  The mobile API base defaults to port 8000 while the dev server runs on
  8001, so set `EXPO_PUBLIC_API_URL`.
- **Tests run on in-memory SQLite.** Postgres-only behaviour (SKIP LOCKED,
  ON CONFLICT, partial indexes, timestamptz) needs a one-off script
  against the local DB, in `/tmp/claude-scratch/<topic>/`, that cleans up
  its rows. This session did that for push delivery and alert claiming.
- **npm installs.** The user's npm has an allow-scripts policy. A plain
  `npx expo install` fails twice over: "fetch failed", then `EALLOWSCRIPTS`.
  Run `EXPO_OFFLINE=1 npx expo install <pkg>` (it writes the SDK-matched
  versions into `package.json`), then a plain `npm install`.
- **Celery.** It needs both a worker and beat (`make backend-worker`,
  `make backend-beat`). Beat drives the weekly summary (daily, 09:00 UTC)
  and push delivery (every 60 s).
- **Checking each commit when one file holds changes for several commits.**
  Run `git worktree add --detach /tmp/claude-scratch/<topic>/wt <sha>`,
  then run pytest with `PYTHONPATH=<wt>/backend`. Without it, the editable
  install loads the main checkout's code instead. Symlink the main
  `mobile/node_modules` into the worktree, and run `ruff format --check`
  too: hand-built intermediate files are where a stray trailing blank line
  slips in.
