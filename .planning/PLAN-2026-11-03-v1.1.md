## Decisions (answered by the user, 2026-11-03)

- **D1 payment stack: RevenueCat.** `react-native-purchases` in the app (needs the dev build, not Expo Go); the backend trusts RevenueCat's webhook and REST API for entitlements, never the client. Price $5.99/month (`00-overview.md`). RevenueCat API keys, the webhook secret and App Store Connect products are the user's to create: build against config with mocks in tests, document the setup in `docs/DEPLOYMENT.md`, and list the sandbox purchase as a manual device check.
- **D2 gating: only new extras.** Premium gates custom categories (V11-P1), data export (V11-P2), rollover (V11-P3), the 12-month trend (V11-06), and unlimited receipts (lifts `free_tier_receipts_per_month`). Price history, matching, price alerts and comparison stay free. A free user sees an upgrade prompt, never an error screen.
- **D3 stores: per-user aliases.** A user's store merge changes only how that user's receipts group (a per-user table), plus automatic normalization of branch numbers and punctuation for everyone. Never rename a shared `stores` row from one user's action.
- **D4 phase docs: switch to V1.1 (V11-07); the stretch item (V11-S1) is out.**
- **D5 waitlist free year (user, 2026-11-04): a RevenueCat promotional entitlement.** A matched waitlist member gets a 1-year promotional grant of the Premium entitlement through RevenueCat's REST API, so D1 holds (RevenueCat stays the only source of Premium). Offer terms: `docs/marketing/decisions.md` #2, #7, #9–#11.

- **Waitlist source.** The waitlist is a Resend audience (`marketing/api/_handler.js`, emails trimmed and lowercased).
  - A Celery task copies its contacts (email, `created_at`, `unsubscribed`) into a `waitlist_entries` table until the claim window closes.
  - New config: `GG_RESEND_WAITLIST_AUDIENCE_ID`, `GG_WAITLIST_CUTOFF` (the date the site switched to `PUBLIC_LAUNCH_STATE=b`) and `GG_PREMIUM_LAUNCHED_AT`.
  - Unsubscribed contacts are included (#10).
- **Who matches.** An account's email equals an entry's, with:
  - the email verified (`email_verified_at` set, or an Apple or Google sign-in);
  - the entry's `created_at` before the cut-off;
  - today within 90 days of `GG_PREMIUM_LAUNCHED_AT` (#9);
  - the waitlist email not yet redeemed.
- **When matching runs:**
  - sign-up with Apple or Google;
  - `verify-email`;
  - `confirm_email_change`;
  - one backfill task over existing accounts.
- **Grant.**
  - Call `POST /v1/subscribers/{app_user_id}/entitlements/{revenuecat_entitlement_id}/promotional` with `end_time_ms` set to the match time plus 12 months (#9), through a new method on `revenuecat_client.py` (`HttpRevenueCatClient` already uses the secret key).
  - Don't send `duration`: RevenueCat's v1 reference marks it deprecated. RevenueCat treats a grant ending within 2 hours of an active promotional's end as a duplicate. Check the current reference (v1 or v2) when building.
  - Then `PremiumService.refresh`.
  - A `waitlist_redemptions` row (unique on the normalized waitlist email, state pending → granted) makes the grant idempotent and retryable: one year per waitlist email.
- **Claim step.**
  - Settings → "Claim your waitlist offer", shown only while the window is open and the user has no waitlist grant.
  - The user enters their waitlist email; the backend sends a confirmation link to it, following the email-change confirmation pattern (`auth.py`). Confirming runs the match.
  - This covers Hide My Email (`@privaterelay.appleid.com`) and a different sign-up email.
  - Run `design-ui` first.
- **Retention (#11).**
  - A beat task deletes `waitlist_entries`, and the Resend audience's contacts, 90 days after `GG_PREMIUM_LAUNCHED_AT`.
  - Redemptions stay with their account.
  - Account deletion must cover the new tables (`tests/api/test_account_deletion.py`).
  - **Account deletion (user, decisions #13):** keep only a salted, one-way hash of the redeemed waitlist email, with no link to the account, until the window closes; then delete it. Account deletion removes everything else. A deleted-and-new account can't redeem the same waitlist email again.
- **Tests.**
  - The cut-off, the window and verified-only matching.
  - Unsubscribed contacts match.
  - Hide My Email doesn't match, but the claim step does.
  - The same waitlist email can't redeem twice.
  - A RevenueCat failure leaves the redemption pending and retries.
- **Docs.** `08-api-contracts.md` (claim endpoints), `07-data-model.md`, and a `verify-grocery-genie` journey. Tick the §6 items it closes.
