## Parallelism and conflict rules

- Wave 1: V11-01, V11-03 and V11-06a run at the same time, each in its own worktree (`isolation: "worktree"`). Only V11-01 adds a migration, so the chain cannot fork.
- Shared files touched by several tasks: `backend/app/models/schemas.py`, `backend/main.py`, `backend/app/core/config.py`, `mobile/app/_layout.tsx`. Merge PRs one at a time; before merging, merge `main` into the next task's branch and rerun its gates.
- Migrations: one per task, revision ids fixed above, never two open at once.
- Mobile: one subagent per screen file at a time.

## Definition of done per task (the coordinator checks every line)

1. TDD: failing test first for each acceptance criterion (AGENTS.md).
2. `/validate` green (backend: ruff check, ruff format --check, pytest, `alembic check` on Postgres, `scripts/check-backend-lock.sh`; mobile: tsc, eslint, jest).
3. Backend suite on Postgres with pgvector (`GG_TEST_DATABASE_URL=...gg_test`), not only SQLite.
4. `/verify-acceptance <story>`: every AC satisfied and tested; add rows to the V1.1 matrix in `docs/prd/13-validation-strategy.md`; `scripts/check-traceability.py` clean.
5. `/verify-grocery-genie`: drive the feature through the API on Postgres; add or update a journey in `.agents/skills/verify-grocery-genie/features/` and its README; `scripts/check-agent-skills.py` clean. Quote the run id.
6. Any covered `verify-*` skill (V11-01: `verify-budget-alerts`).
7. Docs: `08-api-contracts.md`, `07-data-model.md`, `12-analytics.md` as touched.
8. Then: commit, push, open the PR, merge it (user authorized on 2026-11-03: "create PR and merge in the coordinator when the tasks completed is verified /verify-grocery-genie"). Update the status table.
